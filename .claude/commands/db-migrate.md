# Database Migration

Safely manage database schema changes with Alembic:

## Prerequisites
- PostgreSQL running (docker-compose up db)
- Environment variables configured

## Common Operations

### Create New Migration
```bash
cd core
uv run alembic revision --autogenerate -m "description of changes"
```

### Apply Migrations
```bash
cd core
uv run alembic upgrade head
```

### Rollback Last Migration
```bash
cd core
uv run alembic downgrade -1
```

### View Current State
```bash
cd core
uv run alembic current
uv run alembic history
```

## Migration Workflow

1. **Modify Models**: Update SQLAlchemy models in `core/db/models/`
2. **Generate Migration**: Run autogenerate
3. **Review Migration**: Check generated file in `core/db/alembic/versions/`
4. **Test Migration**: Apply to development database
5. **Verify**: Check database state
6. **Commit**: Include migration file in git commit

## Best Practices

**DO:**
- Always review autogenerated migrations
- Test migrations on development DB first
- Include both upgrade() and downgrade() functions
- Use descriptive migration messages
- Backup production data before migrations

**DON'T:**
- Run untested migrations on production
- Delete migration files after they're applied
- Modify existing migrations that are in production
- Skip the review step for autogenerated code

## Troubleshooting

### Migration conflicts
```bash
cd core
uv run alembic heads  # Check for multiple heads
uv run alembic merge heads -m "merge heads"
```

### Reset development database
```bash
docker-compose down -v
docker-compose up db
cd core && uv run alembic upgrade head
```
